# 2026-10-23.3 — Block documents are UTF-8

Kind: mech
Task: the hotty agent's heads-up that SPEC §3.3 now refuses a document
that is not UTF-8 (EINVAL, hotty a07355c). hottyterm already did this.
Commit: (this one)

## What changed

- **A block's document is always UTF-8.** margin copied a file's bytes
  into its HTML as they were, so a file holding Latin-1 or other stray
  bytes gave documents a host refuses. Those blocks then had no surface,
  and the status line showed the EINVAL. `hotDocs.base` now replaces such
  bytes with U+FFFD before it caches the document, so both the measure and
  the placement documents get the replacement. A mermaid block's document
  is an ASCII `cid:` reference. The kit panes' content goes through
  `encoding/json`, which already replaces invalid bytes.
- **hottytea and hottytest moved twice since 2026-10-23.2**, both on
  main and untagged:
  - 5586fd4 (b165920): a hidden surface no longer reports a loss again.
  - 0954c06 (7adebc2): two placements in flight report one loss. The
    lost-resources test now checks that each resource goes once (F37).

  Move to v0.5.1 once the maintainer tags it.

## Tests

`make check` and `make test-race`. `TestHotDocsAreUTF8` gives a heading,
a paragraph, a list item, a table and a code block bad bytes, and wants
each document valid UTF-8 with U+FFFD in it. All five fail without the
fix.

## Notes

- The cells view is unchanged; only the documents sent to a host are.
- Anchors are untouched: they come from parsing the file's bytes, which
  this does not change, so threads on such blocks stay where they were.
