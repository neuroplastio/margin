# 2026-10-22.6 — margin on hotty 0.5

Kind: mech (dependencies only; no code of margin's changed).
Task: the hotty agent's port request: hotty 0.5 is released (spec v0.5.0,
hotty-go v0.5.0 in every module, the kit at hotty-a2ui b1f6b54). On the
local `hotty-0.5` branch, after 2026-10-22.5.
Commit: (this one)

## What changed

- `go.mod`: hotty-go, hottytea, hottytest, hottyedit and hottyterm
  v0.4.0 → v0.5.0; hotty-a2ui cf085ff → b1f6b54.
- `--version` now ends `· hotty 0.5` (2026-10-22.5 reads hotty-go's
  `hotty.Version`).

## Why nothing else moved

- hotty 0.5's `a=field` (§6.4) and `rev` in input and change events are the
  kit's: margin hands every pane event to the kit (`hotPaneEvent`), and the
  kit carries `rev`. margin sends no `a=field` itself.
- The kit's own 0.5 work is HottyPicker's completion (9e13201). margin's
  fields (the palette's query, the search draft, the composer) are plain
  text fields, so it has no completion to port.
- margin reads no caret or selection positions from events, so UTF-8 byte
  positions change nothing here.
- On a 0.5 host the caret starts at the end of a field's value: the
  composer, opened again on a kept draft, puts the caret after it. On 0.4
  it started at the front, so "first", esc, c, " second" read
  "secondfirst"; on 0.5 it reads "first second".
- A 0.4 host answers margin's 0.5 hello with EVERSION, and margin falls back
  to cells as it does on any host that isn't hotty.
