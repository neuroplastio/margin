## What changed

margin is now released the way plx and engram are (D18). Every push to main
that passes `make check` becomes a build on `pkg.neuroplast.io/margin/dev`:
`make dist` builds four static binaries, `engram publish` uploads them as bare
files (`margin/<os>/<arch>`) under one manifest signed by the release key in
KMS, and the workflow reads the build back through the CDN with `engram verify
--fetch`, three attempts like plx's. The goreleaser snapshot pipeline and
`.goreleaser.yml` are gone.

- **Versions.** `internal/version` replaces `main.version`. A channel build is
  `26.10.02-dev.0d7c52f (<full commit>)`; a local build is
  `0d7c52f+dirty (local build)`. The Makefile stamps the commit and the dirty
  flag for `make build`; `make dist` adds the name and the `dev` channel and
  refuses a modified tree.
- **`margin update [commit]`** (`internal/update`) fetches the newest build or
  a named one (full commit or prefix), believes only the pinned key, checks
  the binary's sha256, and renames it over the running executable (symlinks
  followed, temp file beside it, 0755, fsync). It does nothing when already on
  that build, refuses a channel head older than a channel build's own place
  in it, and names the directory when it cannot write there.
- **CI** is one workflow on GitHub-hosted runners: `make doctor` + `make check`
  on pull requests and main (with nvim v0.12.5 from the official tarball,
  pinned by digest), then build and publish on main. All the AWS names are in
  the workflow's `env`; the only credential is the OIDC token.

## Notes

- **The publish needs infra first.** The role `github-pkg-publish-margin` is
  added in neuroplastio/infra; until that is applied, the publish job fails
  at the AWS credentials step and nothing reaches the channel. Re-run the job
  afterwards; publishing a commit twice is a no-op.
- **Tests.** `internal/update` runs every case against a channel published
  into a directory with engram's own `Publisher`, signed by a throwaway key
  and served by `httptest` (`internal/update/testchannel`). The end-to-end test
  in `cmd/margin` builds two real margin binaries with `-tags updatetest`
  (the only build where `MARGIN_UPDATE_SIGNERS` can pin another key), runs
  `update` from the older one and checks `--version` of the file it ran from,
  then refuses a build whose binary was swapped after signing.
- **Why not install.sh.** engram's installer always `tar -xzf`s the artifact,
  so it cannot install a bare binary. The README recipe uses `latest/` (the
  newest build's files under fixed names) and checks the manifest with
  `ssh-keygen` and the binary with a grep for its sha256.
