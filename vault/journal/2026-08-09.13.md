# 2026-08-09.13 — ephemeral stdin reviews: `margin -`

Kind: mechanical
Task: (feedback, `vault/feedback/2026-08-09-stdin-ephemeral-review-feedback.md`
— both bullets; they are one feature: "support piping markdown content via
stdin", and "using --stdin implies --stdout; nothing is stored in
.margin/threads, the review is printed on exit")
Commit: (this one)

## What changed

`margin -` (or `margin --stdin`) now reads the document from stdin and reviews
it ephemerally, closing the pipe-to-pipe loop the feedback asked for:

```
agent -p "draft a plan" | margin - | agent -p "address this review"
```

The mechanics:

- **No persistence, structurally.** A stdin review never touches
  `.margin/threads` in either direction: `Run` skips `loadThreadsForDoc`,
  leaves `m.store` nil (so the save path is the pinned nil no-op), and starts
  no watcher. What the session produces leaves through stdout or not at all.
- **`--stdout` is implied**, per the feedback's second bullet — with nothing
  persisted, printing the review on quit is the only way the work leaves the
  session. `main.go` forces `RunOptions.Stdout` when `--stdin`/`-` is given.
- **The interface moves to the controlling terminal for both streams.**
  `--stdout` already pointed `tea.WithOutput` at `/dev/tty`; stdin mode adds
  `tea.WithInput` on the *same* O_RDWR handle, since stdin is now the
  document. Recorded as F17 — one duplex handle serves both, two opens buy
  nothing.
- **`margin -` with no pipe is rejected, not hung on.** Without a guard,
  reading the "document" from a terminal stdin would swallow keystrokes until
  EOF and then review whatever was typed. Run checks `ModeCharDevice` first
  and errors with "expects markdown piped in; pass a file or pipe one".
- **The export's agent instructions gain an ephemeral variant.** The stock
  preamble tells the agent to reply by editing `.margin/threads/<doc>/<id>.md`
  — in an ephemeral review those files will never exist, and an agent
  following the instruction would write into the void. The ephemeral preamble
  says so: "this review is of piped content — nothing was saved, and there
  are no thread files to reply in. Address each item against the source
  document and report back; the quote under each header identifies the
  block." The file-backed wording is byte-for-byte unchanged. `exportReview`
  gains an `ephemeral bool` (last param) to select between them; the model
  carries it as `m.ephemeral` so `Y` and the on-quit print agree.
- The document is labelled `stdin` in the export header and locators
  (`stdin:12 (^abc123)`) — there is no path to name, and the line number is
  still meaningful within the piped content.

Chose `-` as the primary spelling with `--stdin` as the explicit one (both in
the feedback, "`-" / "--stdin`"), over flag-only (`-` is the convention every
Unix tool already teaches) or dash-only (a flag reads better in scripts).
Chose rejecting a terminal stdin over blocking on it — a hang that ends in
reviewing your own keystrokes is worse than an error that names the fix.

## Verification

`make check` green (build, test, vet). No composer or emulator change — the
`tea.WithInput` addition is program setup, not the pty-writer/render-reader
pair — so `make test-race` is not required by the gate.

New tests: `loadDocFrom` parses piped markdown and names its label (not a
path) in the empty-document error; `Run` with `Stdin` reaches for the
controlling terminal and surfaces its failure (pinning implied `--stdout` at
once); the terminal-on-stdin guard rejects `/dev/null` (a char device, so the
guard is testable without a pty); the ephemeral export contains no
`.margin/threads` pointer and stays ANSI-free, while the file-backed export
keeps its instructions verbatim. CLI side: `--stdin` and `-` both set
`Stdin`+`Stdout` on RunOptions, `--stdin` with a file argument is a usage
error that never reaches the runner, and `--help` mentions the flag.

End-to-end against the real binary in a pty (`script -qec`, document on the
redirect, `q` down the pty): the TUI ran on the controlling terminal, quit
cleanly, and printed `# Review of stdin` with the ephemeral preamble to a
stdout that was a real file — zero ANSI lines in it. No `.margin/threads/stdin/`
(or any new `.margin` entry) appeared in the working directory. `margin -`
with a terminal stdin exits 1 with the pipe-expecting error.

What I cannot verify: how the session *feels* — but nothing about the
on-screen interaction changed this leg; the TUI is the same one EXPORT-03
already put on `/dev/tty`.

## Not addressed, deliberately

Drafts of *unsubmitted* comments still land in the user cache dir keyed by
anchor, exactly as in a file-backed review — principle 3 ("never lose the
user's words") applies to a pipe too, and the feedback's "no persistence"
names `.margin/threads`, not the crash net. The remaining feedback files
(visual mode, todo-review, additional UX/CLI) are future legs; this leg
drained only the oldest item. No question raised.
