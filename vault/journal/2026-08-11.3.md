Commit: (this one)

## What changed

In a tree review, `i` (`inbox.toggle`) swaps the document column for the
comment inbox: every thread file under `.margin/threads/`, newest activity
first. `enter`/`l` on a row opens that thread's document — exactly the
`openTreeFile` a pane open performs, same re-pointing, same session reset —
and lands focus on the block the thread is anchored to, centred, with the
landing recorded in the jumplist so `ctrl+o` walks back. `esc`/`h`/`tab`
return to the document, `q` quits, j/k/g/G move, the wheel scrolls the inbox's
own offset. The tree pane stays rendered beside it, so the reviewer always
sees where a thread lives.

- **The data is a walk of the thread files, not a parse of the documents.** A
  thread is keyed by document path (D9), so `.margin/threads/` already mirrors
  the tree of documents; `loadInbox` walks it and reads each file. No markdown
  is parsed to answer "what threads exist", and nothing is written.
- **A thread whose document left the tree still shows**, dimmed with a
  `[doc not in tree]` tag and a status line on enter — the tree-level form of
  the orphaned-thread rule a single document already follows. Nothing silently
  drops.
- **The inbox refreshes on open, not live.** The item list is rebuilt every
  time `i` is pressed, so an agent comment posted in another document appears
  on the next visit; there is no live watcher for the whole tree yet.
- **Scoped to tree reviews.** A single-document review has no other documents
  to aggregate (D10), so `inbox.toggle` is inapplicable and `i` stays unbound.
- **The inbox has its own scroll offset**, like the pane, so closing it
  returns the reader to exactly where they were in the document.

**What I chose and rejected:** a whole-column view over a tree-pane mode (the
inbox is a reading surface for prose comments, and the document column is
where reading happens; the pane is for files), a key `i` (unbound, and reading
as "inbox"; rejected `c`/`m`/`x` which have or could have mark/comment
meanings), keeping the tree pane visible over blanking it (orientation —
"where does this thread live?" is answerable without leaving the list), one
line per thread with the document path + the collapsed-thread summary text
(the `summary` already strips markup and truncates), and a whole-tree live
watcher deferred (the inbox re-reads on open; live-update is a later slice).

## Notes

- No on-disk format, anchor or thread change — the inbox reads the existing
  thread files and writes nothing. The thread file remains the single source
  of truth; this is a view over it.
- The landing mirrors a cross-document link follow: `openTreeFile` resets the
  jumplist to the new top, so `pushJump` gives `ctrl+o` one hop back to the
  top of the opened document — consistent with how 2026-08-11.2's follow
  behaves.
- Mouse: clicks and hover in the inbox column are inert this slice (the pane
  column still works); the wheel scrolls the list. Click-to-select is a
  later slice.
- An empty inbox shows a `no threads yet` message in the document column; the
  footer carries the count and the key hints.

## For the maintainer to look at

Whether a whole-column view is the right surface for the inbox (vs a mode of
the tree pane, or a pane of its own); whether `i` is the key; whether the
tree pane should stay visible beside it; whether a resolved thread should be
dimmed with a `✓` as built; whether the inbox should refresh live; and
whether the `enter` landing — opening the document and centring the block,
like a link follow — is the jump you expect.

## Demo

```bash
make build
mkdir -p /tmp/inboxtree/docs
printf '# Home\n\nRoot prose.\n' > /tmp/inboxtree/README.md
printf '# Spec\n\n## Setup\n\nThe steps.\n' > /tmp/inboxtree/docs/spec.md
./bin/margin /tmp/inboxtree
```

1. **Build a thread on each document.** In the README, press `j` onto "Root
   prose.", then `c` to comment on it, type something and submit (`ctrl+s`).
   Press `tab`, `enter` to open `docs/spec.md`, `j` onto "The steps.", `c`,
   comment, submit. You now have two threads on two documents.
2. **The inbox.** Press `i` — the document column becomes the inbox: both
   threads, newest first, each row naming its document and the comment text,
   with the focused row carrying `▌`. I chose a whole-column view with the
   tree pane still on the left. Does the inbox read as "everything people
   said across this tree" at a glance?
3. **Jump to a thread.** `enter` on the spec thread — the review switches to
   `docs/spec.md` and lands centred on the block that thread is anchored to,
   status `inbox: docs/spec.md · <comment>`. `ctrl+o` walks back to the top
   of the document. Is landing on the block the jump you want, or should
   enter open the thread's conversation directly?
4. **Return.** `i` re-opens the inbox — the list rebuilt, so an agent reply
   written while you were in the document would appear here. `esc`/`tab`
   close it back to the document, scroll position preserved.
5. **A resolved thread.** In the inbox, note a resolved thread renders dimmed
   with a `✓` — the same signal a collapsed thread in the document uses.
   Resolve a thread (`R`) and reopen the inbox to see it dim. Is that the
   right emphasis for done threads?
