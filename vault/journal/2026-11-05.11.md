# 2026-11-05.11 — the jitter: hotty-go 23af564

Kind: mech (dependency and a regression test); the effect is felt, so it is on
the board's `Needs a look:`.
Task: the hover item, reopened 2026-11-05 by the maintainer's repro: "It jitters
when the table above Try it has a j/k selection and I move the mouse cursor on
text under Try it."
Commit: (this one)

## Cause (found on the real host, reported to gov; fixed in hotty-go)

With the table selected, its tall gutter bar plus the hover bar give Bubble Tea a
frame of identical lines; its hard scrolling (on, and with no option to turn it
off) scrolls a region (`CSI 34;47 r`, `CSI 2 T` or `ESC M`) to move them. The
host scrolls its surfaces with it. hottytea read the scroll and placed the
surfaces again after the frame's ESU, so the host drew them scrolled and then
snapped back: the jitter. Not margin's: margin sends nothing hotty-side on a
hover.

## What changed

- go.mod: hotty-go, hottytea and hottytest at
  v0.6.1-0.20261105162053-23af564543c8. When a frame scrolls a region, the
  output writer puts the re-places inside that frame, before its ESU (or right
  after the write where there is no synchronized output), and tells the program
  nothing, so no erasedMsg-driven relayout follows.
- `TestHottyHoverWithASelectionRepairsInsteadOfRelaying`: the demo document,
  `/Try it`, enter, `k` (the table above), then every block hovered, three
  rounds, against a control run that only selects. The hovering run repairs more
  frames than the control (the reproduction still scrolls) and makes no more
  relayouts.
- `TestHottyHoverPlacesNothingAgain` (no selection) stays.

## Real host

`vault/shots/hover/real-host-selected-table.txt`: before, 130 `a=place` after
the frames' ESUs; after, 72 `a=place`, all before the frame's ESU, none after,
