## What changed

Two new files and a README addition, modeled on kubecom's setup (the same
`version: 2` schema, the same two-archive shape, the same `check`-then-snapshot
workflow and action-artifact upload, pinned to the same `v2.17.1`):

- **`.goreleaser.yml`** — builds `./cmd/margin` for linux/darwin amd64/arm64
  with `CGO_ENABLED=0`, stamping `-X main.version={{ .Version }}` (the one
  stamped var, mirroring the Makefile's `git describe`); a `release` archive
  (tar.gz, carries the binary + LICENSE + README) and a `binaries` archive
  (raw binary, kept for a future tag release), plus `checksums.txt`.
  `snapshot.version_template` is `{{ .ShortCommit }}` — the version is the
  short sha, never a tag.
- **`.github/workflows/release.yml`** — on every push to `main`: `goreleaser
  check` then `goreleaser release --snapshot --clean` (builds into `dist/`,
  publishes nothing — no tag, no release object, no token), then
  `actions/upload-artifact` uploads `dist/*.tar.gz` + `dist/checksums.txt` so
  the run's Artifacts list is the download surface.
- **README + `.gitignore`** — an Install paragraph pointing at the run's
  artifacts (`margin_<sha>_<os>_<arch>.tar.gz` + `checksums.txt`, verify with
  `sha256sum -c`, version shown by `margin --version`); `/dist/` ignored.

## Notes

- **Chosen:** the snapshot + action-artifact mechanism over a tagged GitHub
  release, because the feedback is explicit that there are no semver tags and
  none are planned — and goreleaser's snapshot mode is exactly the no-tag,
  no-publish, build-only shape. Kubecom's `binaries` archive is kept but only
  the tar.gz archives are uploaded (kubecom's own judgment: "double the upload
  for no new bits"). The `binaries` archive produces no standalone file in
  snapshot mode anyway — its artifact path is the per-target build dir
  (`dist/margin_linux_amd64_v1/margin`), which is a goreleaser v2 quirk worth
  knowing if a tag release is ever wired up.
- **What is NOT verified here:** the workflow itself has not run on GitHub —
  I cannot push and watch Actions. What is verified is the config: `goreleaser
  check` passes, a real local `goreleaser release --snapshot --clean` produced
  the four `margin_<sha>_<os>_<arch>.tar.gz` files plus checksums, and the
  built binary reports `margin b54ab05`. `make check` stays green (this leg
  compiles nothing).
- The changelog/announce sections are deliberately absent: this pipeline never
  creates a release, so kubecom's elaborate changelog filters and group
  headings would configure something nothing consumes.
- `make test-race` was not required: nothing touches the composer or the
  emulator.
