## What changed

The maintainer's "mouse wheel speed (3 lines per tick) should be tunable" — the
wheel's fixed 3-line step became a per-run setting:

1. **`--wheel-speed N` on the command line.** `handleWheel` scrolled a literal
   `3` per tick; it now reads `m.wheelSpeed`, a new field on `model`
   (`internal/review/review.go`), defaulted to 3 in `newModelAt`. `RunOptions`
   gains `WheelSpeed int` (0 means "keep the default") and `Run` applies it to
   the model after construction; `cmd/margin` registers the flag and threads it
   through, documenting it in both `--help` and the README.

2. **The clamp.** A configured value below 1 (or the zero default on a
   test-built model) is clamped to 1 inside `handleWheel`, so the wheel can
   never silently do nothing — the default stays the model's 3, and an explicit
   `--wheel-speed 0` is the same as not passing the flag.

**What was rejected:** a runtime command (`:` palette) or a config file. The
wheel step is a hardware-and-preference thing you set once per session, and a
flag is the smallest surface that can be judged — nothing about margin's
on-screen behaviour changes until the maintainer runs it and decides whether 3
was right or the step should scale per-tick differently (e.g. with
high-resolution wheels). J/K keyboard scrolling stays at its own fixed 3, since
the feedback named only the wheel; a shared step setting can follow if the
judgement lands that way.

## Demo

```bash
make build && ./bin/margin --wheel-speed 1 testdata/sample.md
```

1. Scroll the mouse wheel down a few ticks over the document — with
   `--wheel-speed 1` it moves one rendered line per tick, fine-grained.
2. Quit and rerun `./bin/margin testdata/sample.md` — the wheel steps back to
   three lines per tick.
3. `./bin/margin --help` shows the new flag.

Questions for maintainer: is one line per tick fine-grained enough at the
minimum, or should the floor be lower (some wheels send more ticks than lines
of text)? Is a per-run flag the right place for the step, or would it matter
enough to want a session command to change it live? Does the wheel speed want
to also drive J/K keyboard scrolling so both share one number, or is the wheel
being separate (and faster-fine-tunable) a feature?
