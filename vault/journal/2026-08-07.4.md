# 2026-08-07.4 — STORE-01: thread files under `.margin/threads/`

Kind: mech
Task: STORE-01
Commit: (this one)

## What changed

`internal/review/store.go` gives a `thread` a markdown-with-frontmatter form
on disk, and a round trip back — the first half of D5 ("threads persist as
markdown files an agent can read and write directly") actually landing as
code rather than a principle.

**Format.** A thread file opens with `---`-delimited frontmatter carrying
`anchor` and `document`, then the quoted block as a blockquote (the fallback
for anyone — human or agent — who opens the file without margin running),
then zero or more posted comments, each its own `## author — RFC3339
timestamp` section. `marshalThread` writes it; `parseThreadFile` is its
inverse and returns an error rather than a best-effort guess for anything
that does not parse — a thread file failing to load should be surfacing, not
silently dropping a comment, same principle `reattach` (ID-02) applies to a
vanished anchor.

**Layout.** `threadFilePath(root, docPath, anchor)` puts a thread at
`.margin/threads/<docPath>/<anchor-without-caret>.md` — recorded as **D9**.
`docPath`'s own directories are preserved underneath `threads/`, so the
thread tree mirrors the document tree. This is a lay-out decision, not an
interaction one, so I made it rather than asking: CLAUDE.md is explicit that
package layout is mine to decide freely.

**What this deliberately does not do.** Q-0002 is still open, and it names
exactly this leg by anticipation: "STORE-01 is next up and mechanical, so an
agent will design the thread file format without asking. Whatever it picks
becomes the on-disk shape." So the frontmatter carries only what is already
settled — `anchor`, `document` — and nothing for resolved state or a
deletion tombstone. Q-0002's `Blocks:` line does not actually name STORE-01,
only THREAD-01/THREAD-03/EXPORT-05, so building the base format was not
itself blocked — but baking in a guess at the two fields the question is
about would have been exactly the guess it exists to prevent. THREAD-01 and
THREAD-03 will extend this format once Q-0002 is answered; they do not need
to replace it, since both proposed shapes (a boolean, a tombstone) are
additive frontmatter.

Also not done here, on purpose: nothing in the running app calls
`writeThreadFile` or `readThreadFile` yet. `ensureThread` still only ever
creates an in-memory thread, and `Run` still only ever passes `nil` for
`threads`. That wiring — write on submit, load on open, watch for external
changes — is STORE-02, and this leg is the format and the round trip it will
build on, not the integration.

## Notes

Comment bodies are matched up to the next `## ` line (or EOF), so multi-
paragraph bodies with blank lines round-trip, but a body that itself contains
a line starting with `## ` would be misread as the next comment's header.
Not a concern for anything margin itself writes; worth knowing if a thread
file is ever hand-edited.

Timestamps are formatted `RFC3339Nano` and compared with `time.Time.Equal` in
tests, not `reflect.DeepEqual` — a string round trip drops the monotonic
reading and normalises the location, so a `DeepEqual` would fail on data that
is, in every way that matters, unchanged.
