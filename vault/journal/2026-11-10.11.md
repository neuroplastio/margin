# 2026-11-10.11: tree click kept the keyboard, idle spin

The maintainer reported: keys don't reach margin and it lags, and after clicking
tree items the right pane stops taking input.

- A click on a tree file sets `treeFocus`, and nothing but tab/esc/h cleared it,
  so a click in the document left the keys in the tree. A click or press
  outside the tree now hands the keyboard back.
- A surf host's `EventFit` always drew the frame again, which made the host fit
  it again: about 1.5 cores at idle. A fit that repeats the last rows no longer
  draws (`hotState.surfFit`, cleared when a surface is dropped).
- Tree items are clickable on a host (`TestHottyTreeClickSelectsAFile`; element
  ids escape `.` and `/`, e.g. `r.ktree.kdocs_2fspec_2emd`).
- Checked in the demo pane: idle CPU 0 after the fix. Not checked by eye: the
  click-away focus; the maintainer to try it.
