## What changed

Four changes, all interaction decisions the maintainer made directly, so they go
straight into `interaction.md` rather than through a question.

**Headings are commentable.** "This whole section is wrong" is a real comment and
belongs on the heading. `commentable()` split from `markable()`: a heading can
carry a thread, but still has no mark of its own — it rolls up its section, so
the two can never disagree.

**`space` cycles the mark** — unmarked → reviewed → flagged. `r` and `f` remain
for setting one directly. A partially marked section resolves to its roll-up on
the first press, so one keystroke makes it consistent rather than jumping
somewhere unexpected.

**`Y` copies the review to the clipboard.** One section per commented or flagged
block, each naming its anchor and quoting the block so an agent can find it.
Flagged-with-no-comment blocks are included, because "needs attention" is itself
the feedback; reviewed-and-silent ones are omitted. Drafts are excluded but
counted, so nothing goes silently missing.

**`ctrl+enter` submits** in the composer.

Also renamed the leftover `Mdreview*` identifiers to `Margin*`, and
`MDREVIEW_NVIM_CONFIG` to `MARGIN_NVIM_CONFIG`.

## Notes

The clipboard takes two paths deliberately. An external helper — `wl-copy`,
`pbcopy`, `xclip`, `xsel` — is definitive when installed. `tea.SetClipboard`
emits OSC 52 through the terminal, which is the only thing that works on a bare
tty or over SSH. This machine has **no** helper installed and runs a `tty`
session, so OSC 52 is not a fallback here, it is the path. The status line says
which one was used, and does not claim success for OSC 52 since that cannot be
verified from inside the process.

`ctrl+enter` is the second key the host intercepts, after `ctrl+\`. It cannot
work any other way: a terminal sends CR for both enter and ctrl+enter, so nvim
cannot distinguish them, and the embedded emulator does not advertise the Kitty
keyboard protocol to the child, so forwarding the distinction is not possible
either. We only see it because Ghostty speaks that protocol to *us*. It resolves
to the same ex command as every other submit gesture, so there is still exactly
one submit path.

`TestPlainEnterIsANewline` guards the obvious regression.

Two small things the tests caught: bubbletea reports space as `"space"`, not
`" "`; and the seeded headings needed anchors once headings became commentable.
