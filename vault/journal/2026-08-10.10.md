## What changed

The feedback asks for a command that outputs "AI agent skill information" — the
document an agent loads to learn how to use margin — and requires that it teach
the **interactive review loop** end to end: launch margin in a new terminal for
the human, poll for their comments, respond via the CLI, and let the human see
the reply live. Every building block already exists; this leg is the document
that binds them.

- **`review.SkillDocument()`** (`internal/review/skill.go` + the embedded
  `skill.md`): the document, ~100 lines of markdown. Shape: what margin is and
  that the agent is a participant, not an exporter; a table of the **four
  commands** (`margin FILE.md`, `margin export FILE.md`, `margin comments wait
  [--since ID] [--timeout DUR]`, `margin comment add FILE.md --anchor ID
  --text "..." --author agent`); a numbered **interactive review loop** —
  launch (new terminal, never watch it), read the starting state (export),
  wait (`comments wait`, with the full three-outcome exit contract: 0 = lines,
  1 silent = timeout "nothing yet", 1 + stderr = real error), reply (`comment
  add`, and the **live** half: the thread watcher reloads on disk changes, the
  event log is what the agent tails), loop (last line's id is the next
  `--since`); and a **contracts** section — the event log (JSONL, append-only,
  13-char time-ordered ids, file-position tie, torn tail), thread files
  (frontmatter anchor/document/`resolved: true`, the CLI keeps them and the
  log in step), anchors (stable across rewrites; a stale anchor fails loudly).
  Ends with a note that resolving a thread is `resolved: true` in the
  frontmatter, reversible by either side.
- **`margin skill`** (`cmd/margin`): a new top-level subcommand that prints
  the document to stdout and nothing else — no args, no flags, no runtime
  failure path. Mentioned in the root help's Long text and the README.

**What I chose and rejected:**

- **Subcommand `margin skill` over the `--skill` flag the feedback's title
  uses.** Every non-interactive, agent-facing command is already a subcommand
  (`comment`, `comments`, `export`), and the root command is exclusively the
  interactive review launcher with `ExactArgs(1)` validation — a `--skill`
  flag would be the one odd one out and would need to dodge the file-argument
  rule. Rename-cheap either way, so this is a convention call, not a gate.
- **Markdown over plain text** — the output is a document an agent loads, the
  export is already markdown, and inline code/emphasis carries the exact
  command spellings. **A whole interactive loop spelled out over a summary** —
  the feedback's essential requirement is that an agent can run the loop end
  to end, so each step names its exact command and the exit contract is
  explicit rather than assumed.
- **`go:embed skill.md` over a Go string literal** — the document is content,
  and the prose is exactly what the maintainer judges; embedding keeps it a
  readable markdown file instead of an escape-littered literal. Tests pin the
  loop's steps and contracts, not the prose.

No question raised: every decision here is rename-cheap (flag name, format,
verbosity), and the loop's substance is all settled contract (D11/D13/D14 and
the wait command).

Judge:
1. **Command shape:** I made this a subcommand `margin skill`, not the
   `--skill` flag the feedback's title uses. Does it belong in the subcommand
   tree with `comment`/`comments`/`export`, or do you want the literal flag?
2. **The loop's length:** I spelled out all five steps with exact commands and
   the three-outcome wait contract. Is that the right amount — enough to run
   end to end, not so prescriptive it gets stale — or is a step missing /
   over-specified?
3. **The contracts section:** is the event-log / thread / anchor material the
   right depth, or does the loop want less theory and more recipe?
4. **Read it as an agent would:** running the loop above from the document
   alone — did anything in it mislead you, and is the `resolved: true`
   resolution advice where an agent would think to look for it?

(What I chose: subcommand `margin skill`, markdown output, the whole loop
spelled out, `go:embed` over a string literal. What I rejected: the `--skill`
flag spelling, plain text, a summary that names commands without a loop, and
hand-building the string in Go.)
