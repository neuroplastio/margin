## What changed

The maintainer's agent loop hit two built-in sources of guidance giving
different advice: the export note's "edit its markdown file" for replies, and
the skill document's "prefer the CLI". The skill document is the loop that has
been settled and tested, so the export note is the one that moved.

- **The export note now recommends the CLI for replies.** It opens with
  `margin comment add FILE.md --anchor <id> --text "..." --author agent` — the
  anchor id is in parentheses in the block header — and says why: "the CLI
  keeps the thread file and the event log in step."
- **The file edit stays, but only for resolving.** No resolve CLI exists yet
  (an M2 item), so `resolved: true` in the thread file's frontmatter is still
  the agent's only way to mark a thread done, and the note keeps that path,
  with the `.margin/threads/<path>/<id>.md` spelling the old note used.
- **The tradeoff is stated**, which is the feedback's minimum ask: "a direct
  file edit reaches the human (the thread watcher reloads it) but writes no
  event-log line." The same sentence the skill doc's threads bullet already
  ends with.

**What I chose and rejected:** the skill's direction over the export's (the
skill is the settled, tested loop — journal 2026-08-10.10); keeping the resolve
instruction in the note rather than deleting it (nothing else tells an agent
how to resolve); naming the tradeoff in the note rather than only in the skill
(the feedback's "at least mention the tradeoff" — an export-only agent gets the
whole truth from the export). Rejected: editing the skill instead — it already
says the right thing; and a resolve CLI, which is real M2 work, not a docs fix.
