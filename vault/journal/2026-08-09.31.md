## What changed

The maintainer's ask: "dedicated CLI subcommands/flags so agents can
programmatically extract comments and add/append their own comments without
driving the interactive TUI." Extraction was already served two ways — `--stdout`
prints the whole review, and the thread files are plain markdown an agent reads
with ordinary file tools (D5). The genuinely missing half was the *write* side:
today an agent replies by hand-editing a thread file, and it is easy to get the
frontmatter or the `## author — timestamp` header subtly wrong.

This leg adds the write half as a new `margin comment add` subcommand:

```
margin comment add FILE.md --anchor ^abc123 --text "fixed in rev 3" [--author agent]
```

It is deliberately a thin wrapper, not a parallel implementation:

1. `review.AddComment` (`internal/review/cli.go`) resolves the review root,
   parses the document, finds the block by anchor, loads the existing threads,
   appends the comment, and writes through the *same* `writeThreadFile` /
   `marshalThread` the TUI's `dismiss` uses. The thread file on disk is
   byte-for-byte what a reviewer typing the comment would have produced, so
   reattach, the watcher and the export all see it with no format work.
2. The anchor must name a **commentable block that exists** in the document.
   An agent working from a stale export gets `no commentable block with anchor
   ^deadbeef in FILE.md`, not a silently-created thread nobody will ever see —
   the same "surface, don't drop" ethos reattach applies to a vanished anchor.
   Accepts the anchor with or without the leading `^`.
3. `--author` defaults to the current OS user via `review.DefaultAuthor()`
   (falls back to "agent"), so a reply is never attributed to an empty name.
   `--anchor` and `--text` are cobra-required flags, so a wrong invocation
   shows usage while a runtime failure (missing block, unwritable store) shows
   only the error.

**What was rejected:** a full non-interactive `margin export` subcommand for the
extract half. It adds nothing an agent cannot already do with `--stdout` or by
reading the thread files directly, and it would need a decision about marks
(session-only, so a non-interactive export would render every block unreviewed).
Left in the feedback file as the residual for a future leg if the maintainer
wants a one-shot extractor after all.

## Verification

`make check` green (build, test, vet); `make test-race` green.

New tests in `internal/review/cli_test.go`:
- `TestAddCommentCreatesThreadFile` — the thread file lands under
  `.margin/threads/doc.md/<id>.md`, carries the block's text as the quote, and
  the comment round-trips with author and body.
- `TestAddCommentAppendsToExistingThread` — a second call appends, not
  overwrites.
- `TestAddCommentAcceptsAnchorWithoutCaret` — `abc123` and `^abc123` are the
  same block.
- `TestAddCommentRejectsUnknownAnchor`, `TestAddCommentRejectsEmptyText` — the
  two failure modes an agent can hit.
- `TestAddCommentWritesFileAnAgentCanRead` — the written file re-parses and
  reattaches (not orphaned), so a reopened review shows the reply.
- `TestDefaultAuthorFallsBackToAgent` — never an empty author.

New tests in `cmd/margin/main_test.go`:
- `TestCommentAddReachesTheHandler` — flags land in the AddComment call.
- `TestCommentAddDefaultsAuthorToCurrentUser`.
- `TestCommentAddRequiresAnchor` / `RequiresText` / `RequiresAFile` — cobra
  required-flag and ExactArgs paths.
- `TestCommentAddPrintsWhereItLanded` — the path of the written thread file.
- `TestCommentAddSurfacesRuntimeError` — runtime errors print no usage block.
- `TestHelpMentionsCommentAdd`.

Verified end-to-end against the real binary on a stamped test document: the
command wrote `.margin/threads/doc3.md/abc123.md` with the expected frontmatter,
quote, and `## agent — <timestamp>` header.

No open questions raised.

## Demo

```bash
make build && ./bin/margin --stdout testdata/sample.md   # find an (^id) anchor
./bin/margin comment add testdata/sample.md --anchor ^<id> --text "your reply" --author agent
./bin/margin testdata/sample.md                          # open: the reply is attached
```

Questions for maintainer: is `margin comment add` the right shape, or do you
want a `margin comment` tree with future subcommands (e.g. `list`, `resolve`)?
Should `--author` stay OS-user-defaulted, or should an agent always name itself
explicitly? Is the missing-block hard error right, or should a stale anchor
create an orphaned thread that shows up in the interface instead?
