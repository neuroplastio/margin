## What changed

The feedback asked for a command an agent polls to learn "the reviewer left a
new comment" without re-exporting the review on a timer. The event log
(2026-08-10.7, D13) already records every thread mutation; this leg is the
reader half D13 left "to be judged in a later leg".

- **`review.WaitEvents(path, since, timeout)`** (`internal/review/cli.go`):
  resolves the review root from `path` (the CLI passes `"."`, the cwd), then
  polls `.margin/events.log` and returns the raw log lines of every event
  strictly after the one whose id is `since` — the whole log when `since` is
  empty. A timeout of 0 waits forever; a positive timeout that elapses with
  nothing new returns `ErrWaitTimeout`. Output is the log's own
  tab-separated lines, in file order, so an agent parses the same shape it
  would `tail`, and takes the last line's id as the next `--since`.
- **`readEventsAfter(root, cursor)`** (`internal/review/events.go`): the cursor
  is a *position in the file*, not a string to compare — D13's rule that
  same-millisecond ties resolve by file order. It matches the id, returns
  everything after its line; an id matching no event is an error, not a silent
  "before everything" (the "surface, don't drop" ethos).
- **`margin comments wait [--since ID] [--timeout DURATION]`** (`cmd/margin`):
  a new `comments` subcommand tree holding `wait`. Exit contract (the felt
  part): **0** = new events printed; **1** = timeout with nothing new, *silent*
  — the poller's "nothing yet, try again" signal; **1** with a stderr message =
  a real error (broken log, unknown `--since`). Timeout vs error is told apart
  by stderr being empty, deliberately — a quiet no-op is the normal outcome of
  a poll, and a `waitTimeoutError` would have made the two indistinguishable
  anyway. `--since` defaults to empty (everything is new), `--timeout` to 0
  (wait forever).

**Also fixed, as it fell out:** `resolveReviewRoot` skipped a *directory*'s own
marker — for `path="."` it walked up from `filepath.Dir`, so a cwd with its own
`.git`/`.margin` was never the candidate, and a stray marker in an ancestor won
(the wait command's first smoke run resolved the repo root to `/tmp` because of
a leftover `/tmp/.margin`). It now starts the walk at the path itself when the
path is a directory. File paths are unchanged; a test pins the directory case.

**What I chose and rejected:** the blocking-poll shape over a one-shot
`list`/`since` read — the feedback's word is "wait", and the agent loop wants
"block until the reviewer speaks", not a busy re-poll; the exit contract above
over a distinct timeout exit code (a code for "nothing happened" is information
an agent has to special-case, and stderr silence already carries it); raw log
lines as output over a reformatted digest — the log line *is* the contract
(D13), and reformatting would force an agent to learn two shapes. Rejected
printing the last id as a convenience footer: the lines are already the
machine's answer, and a footer would pollute a pipe an agent feeds back in.

No question raised: the one decision with lasting weight — same-millisecond
cursor semantics — is D13's, and the rest of the surface is rename-cheap.

waiter which printed the new line.

## For the maintainer to look at

The exit-code/stderr contract is the felt surface: is **timeout = quiet exit 1,
error = exit 1 with a message** the right shape for an agent loop, or do you
want a distinct exit code for timeout? And is printing the raw log lines the
right output, or should an agent get something friendlier?

## Demo

```bash
cd <a dir with .git or .margin>        # a review root
make build
./bin/margin testdata/sample.md        # in one terminal; comment on a block (c), submit
./bin/margin comment add testdata/sample.md --anchor ^b36ebc --text "agent reply" --author agent
# now watch the reviewer's next comment land:
./bin/margin comments wait --since $(tail -1 .margin/events.log | cut -f1) --timeout 60s
# leave a new comment in the TUI, and the wait returns its line and exits 0
```

Judge:
1. **Timeout shape:** run `comments wait --since <newest-id> --timeout 5s` with
   nothing arriving. It exits 1, prints nothing. Is silent-exit-1 the right
   "nothing yet" for your agent loop, or should timeout be a distinct exit code
   (say 2) so a script can tell "no news" from "error" without checking stderr?
2. **Output shape:** the command prints the raw `.margin/events.log` lines
   (id, timestamp, type, doc, anchor, author, comment index). Do they read
   well enough for an agent to act on, or would a friendlier one-line-per-event
   digest (e.g. `^b36ebc: agent replied (comment 2)`) be worth the second
   format?
3. **No `--since` = everything is new:** the first call on a log with history
   returns it all immediately (the agent's initial state). Does that match how
   you'd want a polling loop to start, or should the first call with no
   `--since` wait for the *next* event only?
4. The command's own resolve: it needs a review root but takes no file, so it
   resolves from the cwd. Run it from a subdirectory of a repo — it should
   find the repo's `.margin`. Does that surprise, or is cwd the right anchor?

(What I chose: blocking poll, raw log-line output, timeout=quiet exit 1, cwd
resolution. What I rejected: a one-shot list command, a reformatted digest, a
distinct timeout exit code, and a `margin comments wait FILE.md` that would
have added a file argument D13's surface never named.)
