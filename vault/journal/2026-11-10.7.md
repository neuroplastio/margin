# 2026-11-10.7: leg 9, the open thread's comments on surfmd

Kind: felt. The comments of an open thread are drawn by hotty-surf now.
Task: vault/knowledge/hotty-surf-port.md, leg 9.
Commit: (this one)
Agent: Margin Agent on Claude Code.

## What changed

- `comments.go`: a thread's visible comments are one `surfui` stack, a comment
  each: a head (the author in bold, `· age` quiet and small, and the
  `✎ edited, unsaved` / `[deleted]` marker) over the text as `surfmd.Convert`
  makes it (`HardWraps`, `GFM`, `Compact`). A deleted comment's text is muted.
  It is drawn in cells at the box's inner width, as tall as it is
  (`Draw(inner, 0)`), and margin asks the layout where each comment is
  (`BoxOf`): the focused comment's text carries the focus bar, and each comment
  has its subspan. The drawing is kept per thread (`commentDraws`) and made
  again when a comment, an age, an edit or the width changes.
- Gone: the kit pane for the thread (`threadID`), `commentParagraphs` (a typed
  line break is `HardWraps`, a fenced block is Markdown's own), the A2UI
  components of the conversation.
- On a host the comments are still cells inside the box (they were before):
  the conversation is not a surface. A surface for them is leg 10's question.
- Tests: `comments_test.go` (Markdown renders without its marks; the drawing is
  kept and made again), the span, bar and line-break tests follow the new rows.

## Not done

- `surfmd.Highlight` is not wired: a fenced block in a comment uses the
  block's own lexer (go, surf) or is plain. margin's document column
  highlights with chroma; mapping chroma's tokens to `surfui.Span` roles
  (`syn.*`) is a leg of its own.
- Links in comments are not followed (the text only), as before.
