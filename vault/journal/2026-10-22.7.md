# 2026-10-22.7 — The release's stamp check reads the hotty part

Kind: mech (one line of the release workflow).
Task: the Release run on b3f849c (39765104235) failed in "build the
binaries", so the first hotty 0.5 build reached no channel. A fix to
2026-10-22.5's leg.
Commit: (this one)

## What changed

- **"Check the stamp"** in `.github/workflows/release.yml` greps the build's
  `--version` for `^margin <name> (<commit>)$`. 2026-10-22.5 put
  ` · hotty 0.5` after the commit, so the `$` no longer matched. The check
  now wants `^margin <name> (<commit>) · hotty X.Y$`: it proves the hotty
  part as well as the name.
- 2026-10-22.5 checked the readers that cut the name out (`cut -d' ' -f2`)
  and the packages' checks, but not this one. The Homebrew check
  (`^margin <release> `) and the AUR seed's substring match still pass.

## Tests

`make check` and `make test-race`. The workflow has no local runner, so I
ran the step's script by hand on binaries built at b3f849c with `make
dist`'s ldflags. A dev stamp (`margin 26.10.22-dev.b3f849c (…) · hotty
0.5`, the line CI printed) and a stable one (`26.10.22` as the tag) both
pass. A line without the hotty part fails. The `·` matches in the C locale
too.
