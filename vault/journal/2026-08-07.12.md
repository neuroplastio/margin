# 2026-08-07.12 — SCROLL-01: decouple the scroll offset from focus

Kind: mech
Task: SCROLL-01
Commit: (this one)

## What changed

`clampScroll` used to recompute `m.scroll` from the focused entry's span on
*every* render, unconditionally. That was fine as long as nothing else ever
set `m.scroll` — which was true until now, since SCROLL-02 (page keys) and
SCROLL-03 (mouse wheel) don't exist yet — but it meant the offset was never
actually something the user could own: the moment either of those lands and
sets `m.scroll` directly, the very next render would derive a fresh value
from focus and stomp it, undoing the scroll before it was visible.

**The fix.** `model` gains `scrollAnchor cursor` — the focus position
`clampScroll` last pulled the viewport to. `clampScroll` now only re-derives
the offset from the focused span when `m.at != m.scrollAnchor`, i.e. focus
has actually moved since the last time it was asked; otherwise it returns
`m.scroll` as-is, clamped only to stay within `[0, total-viewport]` so a
shrinking document (or a shrinking terminal) can't leave it pointing past
the end. `scrollAnchor` starts at `cursor{entry: -1, comment: commentNone}`
— an entry index no real cursor ever has — so the very first render still
anchors once and opens with focus in view.

This is the prerequisite the board named it as: SCROLL-02 and SCROLL-03 can
now set `m.scroll` directly and have it hold across a render, as long as
focus does not move underneath it. Neither key nor wheel handling is added
here — this leg only makes the offset survive being set.

## What this deliberately does not do

No new keybinding, no mouse handling, nothing a person can trigger
differently than before — today nothing sets `m.scroll` except
`clampScroll` itself, so this leg has no observable effect on the running
app. It is purely the internal seam SCROLL-02/03 build on. Which of them
carries focus along with the viewport and which doesn't is still an open
felt decision (see the board), untouched by this leg.

## Verification

`make check` is green. `make test-race` also green — run out of caution
since this touches the render/focus path that the composer's cursor
placement (`View`) depends on, even though nothing here touches the
composer or emulator directly.

New tests in `internal/review/review_test.go`:
`TestClampScrollPreservesScrollWhenFocusUnchanged` sets a scroll offset by
hand with focus held still and asserts `clampScroll` returns it unchanged
(and is idempotent on a second call) rather than snapping back to the
focused span. `TestClampScrollFollowsFocusOnceItMoves` confirms focus-follow
still works once `m.at` actually changes.

No question raised. Board's `Awaiting review:` stays on **PARSE-02** — this
leg did not touch it; SCROLL-01 was the only unblocked `[mech]` item left,
per M3's own note that the single-document navigation items are not gated
by Q-0001.
