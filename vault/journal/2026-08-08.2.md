# 2026-08-08.2 — Heading hierarchy: weight and colour by depth

Kind: felt

## What changed

`vault/feedback/` held three items after 2026-08-08.1 addressed the oldest.
Feedback preempts the board; the next-oldest by the batch's own numbering is
`2026-08-08-2-heading-hierarchy.md` (RENDER-05), so that is this leg.

Before touching rendering I checked what `block.text` actually holds for a
real heading, because `seedDoc`'s fixture writes it with the `##` markdown
prefix still attached (`"## Retry policy"`) and I did not want to build
against a fixture that lies about the real parser. A one-off program against
goldmark confirmed `ast.Heading.Lines()` covers the text content only — the
`#` markers are syntax, not content, and are never in the raw span `parse.go`
reads. So a heading parsed from a real file already renders as clean text
with no literal `#`; `seedDoc` is just hand-authored ahead of PARSE-01/02 and
was never updated to match. Nothing to fix there — it only matters as
context for why "strip the markdown syntax" (RENDER-04's rationale for block
quotes) was already true for headings and not the gap the feedback was
naming. The actual gap, confirmed by re-reading `review.go`'s render loop,
is that every heading — level 1, 2 or 3 — went through one `headStyle`
(bold, colour 212), so `level` was parsed and stored but never reached the
screen.

Fixed with the first of the feedback's three listed ideas: **font style**,
not the other two. I rejected left-padding indentation because the
feedback's own constraint flags it as costing measure width and needing a
closer look than one leg allows; I rejected a gutter level hint because the
gutter is a fixed 3-column budget already spent on the focus bar and the
section's roll-up mark, and the feedback says a hint there "has to fit
alongside those or widen it" — also more than this leg should decide alone.
Weight and colour cost neither the gutter nor the measure, so it is the
smallest version that can be judged, per the operating guide's bias toward
shipping something over parking the question.

`headingStyle(level int) lipgloss.Style` (`review.go`) replaces the single
`headStyle` var with three, indexed by depth and clamped so a level-4+
heading (none exist in `testdata/sample.md`, but goldmark allows up to 6)
falls back to the deepest defined style instead of panicking:

- **Level 1** — bold, colour 212 (unchanged from before; the most prominent
  stays most prominent).
- **Level 2** — not bold, colour 183 (plain-but-coloured, a step down).
- **Level 3+** — not bold, colour 245 (dim, closest to body text weight).

The roll-up mark in the gutter and the focus bar are untouched — this leg is
only the heading text's own styling.

## What this deliberately does not do

No indentation, no gutter glyph, no combining the two — the feedback
explicitly says its three ideas "combine" and a gutter hint plus a weight
difference might be enough, but committing to a gutter change is exactly the
kind of thing worth its own judged leg rather than bundling into this one
sight-unseen. If weight and colour alone do not read at a glance, the gutter
hint is the next thing to try, not a bigger version of this leg.

Also did not touch inline markup (`**bold**`, `` `code` ``) inside heading
text — that is RENDER-06, a separate item still in the backlog.

## Demo

```
go run ./cmd/margin testdata/sample.md
```

`testdata/sample.md` has all three levels (`#`, `##`, `###`). Scroll through
it and answer:

- Scanning quickly, can you tell a `#` from a `##` from a `###` without
  reading the text, just from weight/colour?
- Is level 1 (bold, bright pink/212) still the one that draws the eye first,
  or does it now compete with something else on screen (the focus bar,
  flagged marks)?
- Is level 3 (dim, 245) legible enough, or does it fade too close to
  reviewed/dimmed body text (240) and become hard to find while unreviewed?
- What I chose: font weight and colour only, no indentation, no gutter
  glyph. What I rejected: left-padding (measure cost) and a gutter hint (gutter
  already full) — both flagged in the feedback as needing their own look
  rather than a default guess.
