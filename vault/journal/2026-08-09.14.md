## What changed

Backspace in the command palette now cancels exactly where there is nothing
left to edit, and only there:

- **`:` then backspace closes the palette.** The maintainer's words: "It
  should cancel the palette (erase the `:`)." Previously backspace on an
  empty query did nothing and the palette sat open.
- **Backspace at a staged command's seed closes too, like `esc`.** `m` (or
  `s`) opens the palette seeded with `mark ` / `goto `; backspace there used
  to rewind to the bare command list (CMD-05's choice), which the todo-review
  feedback rejected: close/reset instead.
- **Typed characters still delete one by one.** Inside a value stage a typed
  value character is ordinary text — `mark r` backspaces to `mark ` first,
  and only the next backspace, at the bare seed, backs out. Editing text
  never closes anything.

One uniform rule in `handlePaletteKey` (`internal/review/review.go`):
backspace deletes typed text; when the next deletion would undo structure
(the `:` itself, or a staged seed), it cancels.

Chose applying the same close-on-seed rule whether the seed came from the
`m`/`s` keys or from typing `:mark ` by hand — the visible state is
identical, the model does not record how the palette was opened, and two
meanings for one key at one visible state is worse. Rejected: keeping the
rewind for hand-typed seeds (inconsistent), and tracking the open-origin to
tell them apart (state to carry for a distinction the feedback does not ask
for). The demo asks about exactly this.

## Verification

`make check` green (build, test, vet). No composer or emulator change —
`handlePaletteKey` runs in the host's Update loop, not the pty-writer /
render-reader pair — so `make test-race` is not required by the gate.

New tests (`palette_test.go`): `:` + backspace cancels with the query
cleared; typed characters delete one by one with the palette staying open
until the last is gone and one more backspace closes it; `m`'s staged seed
backspaces to a close, not a rewind (pins the query is `""`, not `"mark"`);
and a typed value character deletes before the bare-seed backspace cancels.

What I cannot verify: whether cancel-on-backspace *feels* right at the
keyboard, and whether the uniform seed rule ever closes the palette when you
expected to keep editing — that is the demo below.

## Demo

```
make build && ./bin/margin README.md
```

1. `:` — the palette opens at the bottom. Backspace — it should close
   outright (the `:` is erased), document untouched.
2. `:` again, type `mar` — the list filters. Backspace three times — the
   characters delete one by one and the palette stays open on the now-empty
   query. One more backspace — it closes.
3. `m` — the palette opens staged on `mark `, listing `reviewed`/`flagged`.
   Backspace — it closes entirely, like `esc`; it does NOT fall back to the
   bare command list.
4. `m` again, type `r` (query `mark r`) — backspace deletes the `r`, back
   at the value list; the next backspace closes.

Questions: is closing right even when you reached the seed by typing
`:mark ` by hand (same visible state, same rule), or should a hand-typed
seed rewind while a key-seeded one closes? Does backspace now ever close
the palette when you expected it to keep editing? Chose one uniform rule —
cancel exactly where there is nothing left to edit — over distinguishing
key-seeded from hand-typed seeds, which is the case to answer for.
