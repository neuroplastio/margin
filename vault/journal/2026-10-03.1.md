# 2026-10-03.1 — a stable channel, cut from a tag

Kind: mechanical (the stamp, the guards and the notes are checked locally;
the workflow's first real run is the first release).
Task: maintainer direction — a stable channel and a release pipeline driven
by git tags: tag → GitHub release → publish to stable, CalVer (D21).
Commit: (this one)

## What changed

- **`.github/workflows/release.yml`** also runs on a tag named for its day
  (`26.10.03`). The channel and retention follow the ref: dev and 30 days for
  main, stable and for good for a tag. A tag's run checks the tag is a day,
  on main, and the only release on its commit; builds with
  `make dist RELEASE=<tag>`; makes the GitHub release (the binaries, the
  changes since the previous release); publishes the same files to
  `margin/stable` and verifies them; and attaches the signed manifest to the
  GitHub release. The check job's concurrency group is now ref and commit
  for a push, so a tag pushed right after its commit no longer cancels
  main's check.
- **Makefile**: `RELEASE=YY.MM.DD` names a dist build after the tag and
  stamps `stable`, refusing a tag that is not at HEAD; `make release` tags
  HEAD with today's UTC date and pushes the tag.
- **README**: Install leads with stable and names both channels; a new
  Releasing section, with how to replace a release under its name.
- `margin update`'s help says it follows its own channel, and that the
  channel is built in like the server and the key.
- **infra** (`neuroplastio/infra`, `release_tags`): margin's publish role
  also trusts `refs/tags/??.??.??`.
