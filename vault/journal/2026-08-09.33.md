## What changed

Journal 2026-08-09.31 built the write half of the CLI-automation feedback
(`margin comment add`) and deliberately left the extract half behind, on the
grounds that `--stdout` already serves it. It does not quite: `--stdout` runs
the full interactive review first and prints on quit, which needs a terminal
and a human to press keys. The residual bullet stayed in the feedback file, and
the oldest unaddressed feedback item is this leg. So now the extract half
exists too:

```
margin export FILE.md [--include-resolved]
```

`review.Export` (`internal/review/cli.go`) parses the document, resolves the
review root, loads the thread files exactly as `Run` does, reattaches, and hands
the whole thing to the *same* `exportReview` call `Y` and `--stdout` use — so
the bytes an agent reads in a pipe are byte-identical to the review Y copies.
`cmd/margin` wires it as a top-level `export` subcommand next to `comment`,
with the same `--include-resolved` flag the root export paths already have and
the same runtime-error discipline (SilenceUsage on the command; a missing file
shows the error, not the help text).

**The marks decision, made rather than raised.** Marks are session-only — they
persist nowhere — so a headless export genuinely cannot know which blocks a
reviewer has marked reviewed or flagged. The most defensible option is to
report exactly what is on disk: the export's summary reads `0 of N blocks
reviewed` and no block is marked `flagged, needs attention`. That is honest
(not a claim about a past session) and keeps the headless output on the exact
same `exportReview` shape as the interactive ones. Alternatives rejected: an
extra "no marks exist" preamble (noise an agent has to parse), and a bespoke
headless-only summary format (a second export shape to maintain and drift).
Worth revisiting if marks ever become persistent — then this leg is a one-line
change to pass the loaded marks in.

## Demo

(mechanical — nothing on screen changed; the demo is the command itself)

```bash
./bin/margin export testdata/sample.md                      # the review, straight to stdout
./bin/margin export testdata/sample.md --include-resolved   # resolved threads back too
./bin/margin export testdata/sample.md | agent -p "address this review"
```

The 0-of-N summary is the deliberate consequence of marks being session-only;
if that reads wrong when a reviewer *has* marked things, marks persistence is
the thing to build, not a wording change here.
