# 2026-08-07.7 — STORE-02 (partial): wire thread persistence into the running app

Kind: mech
Task: STORE-02 (load-on-open + write-on-submit slice; fsnotify split out as STORE-03)
Commit: (this one)

## What changed

STORE-01 built the thread file format and its round trip but never called
either half of it — `ensureThread` only ever created an in-memory thread, and
`Run` always passed `nil` for `threads`. This leg wires both directions:

**Load on open.** `loadThreadsForDoc(root, docPath)` (`store.go`) reads every
`.md` file already on disk for a document's thread directory and returns them
keyed by anchor. A missing directory is not an error — nothing has been said
about the document yet — but a thread file that exists and fails to parse is:
same "surface, don't drop" reasoning `readThreadFile` already carries, one
level up. `Run` computes `root = filepath.Dir(path)`, `docPath =
filepath.Base(path)` — matching the docstring `newModelAt` already had about
root being "today, the lone document's directory" — calls
`loadThreadsForDoc`, and passes the result into `newModelAt` instead of `nil`.
`reattach` (already wired since ID-02) is what matches the loaded threads back
onto the freshly parsed blocks.

**Write on submit.** A new `threadStore{root, docPath}` on `model` is what
`dismiss` saves through after a comment is posted or edited — one call,
`m.store.save(t)`, right where `t.posted` is already being mutated. `save` is
a nil-safe method: a `*threadStore` of `nil` just returns `nil` rather than
writing anything, and `newModelAt` never sets one. Only `Run` does. This is
what keeps every existing test — and every future one that builds a model
directly — from suddenly writing to `.margin/threads/` under the test
process's working directory the first time it exercises a submit.

**What this deliberately does not do.** No live reload: an agent writing a
thread file while margin is already running is not picked up until the next
open. That needs a filesystem watcher wired into the Bubble Tea update loop as
a new message type, which is a materially different piece of work from a
plain function call — different enough that bundling it into this diff would
have blown well past a leg's size, and it was the harder of the two halves the
STORE-01 journal named ("write on submit, load on open, watch for external
changes"). Split off as **STORE-03** on the board. No new dependency
(`fsnotify`) was added in this leg for the same reason.

Also out of scope, and correctly so: deletion and resolution are still not
representable in a thread file — Q-0002 is still open, and nothing here
touches the frontmatter shape STORE-01 chose.

## Verification

`make check` is green. `make test-race` is also green — this leg touches
`dismiss`, which is the composer's submit path, so ran it even though nothing
in the emulator or the pty bridge changed.

New tests:
- `store_test.go`: `TestLoadThreadsForDocReturnsEveryThreadOnDisk` (and that a
  thread for a different document does not leak in),
  `TestLoadThreadsForDocMissingDirIsNotAnError`,
  `TestLoadThreadsForDocSurfacesAMalformedFile`,
  `TestThreadStoreSaveWritesTheFile`, `TestNilThreadStoreSaveIsANoop`.
- `review_test.go`: `TestSubmitPersistsThroughTheStore` (a model with a store
  set writes the submitted comment to disk, round-tripped back through
  `loadThreadsForDoc`), `TestSubmitWithoutAStoreDoesNotTouchDisk` (the default
  — every other test — stays memory-only, asserted by checking `m.status`
  never reports a save error, since a real "did it touch the filesystem"
  check would need to know a path to check, and the whole point is that there
  isn't one).

Nothing here is felt: no key changed, nothing new renders. The board's
`Awaiting review:` stays on PARSE-02.
