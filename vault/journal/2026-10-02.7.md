# 2026-10-02.7 — margin-launcher, the thin binary a package installs

Kind: mechanical (fetch, hand-over and install are tested end to end with
real binaries, and checked against the live channel).
Task: maintainer direction — a published binary in the AUR that still
updates: an opt-in thin launcher from engram's `enlaunch` (D20).
Commit: (this one)

## What changed

- **`cmd/margin-launcher`**: `enlaunch.Main` with margin's channel and
  pinned key. It runs `~/.local/margin/bin/margin`; with nothing there it
  fetches the channel's newest margin first. 6 MB stripped, none of
  margin's interface in it.
- **`margin update`**, in a margin the launcher started (`ENLAUNCH_HOME`),
  installs the build it picks into the home and moves `bin`; it no longer
  replaces the file it runs from there. Started any other way, it is D18's.
- **`make dist`** builds `margin-launcher_<os>_<arch>` beside each margin,
  and the workflow publishes both names to the channel.
- **The server is pinned** like the key: `MARGIN_PKG_URL` moves it only in
  a `-tags updatetest` build (`seams_updatetest.go`), so neither a released
  margin nor its launcher can be pointed elsewhere.

## Tests

- `TestTheLauncherFetchesMarginAndUpdateMovesIt`: the launcher in a
  read-only directory, an empty home. The first launch fetches margin a
  and runs it; `margin update` installs b into the home; the next launch
  is b; neither the launcher nor a's file was written.
- `TestTheKeyAndTheServerCannotBeMovedInARealBuild`: built as a release
  is, both variables set, and update and the launcher still read
  pkg.neuroplast.io with the release key.
- `TestUnderALauncherTheBuildGoesIntoItsHome`, and enlaunch's own suite
  (fetch, hand-over, `ENLAUNCH_FETCH`, preload and seed, the key and the
  hashes, pruning).
- Live, against pkg.neuroplast.io: `ENLAUNCH_PRELOAD=<dir>` filled a seed
  with 26.10.02-dev.ea0e0df (only `builds/` and `bin`, readable by all),
  and a first launch with an empty home fetched it and ran `--version`.

## Demo recipe

After this is published:

1. Fetch `margin-launcher_linux_amd64` from the channel and run it as
   `margin --version` with `HOME` pointing somewhere empty: it says it is
   fetching, then prints the newest build.
2. Run it again: no fetch line.
3. `margin update` once a newer build is out: it names the home it
   installed into, and the next `margin --version` is the new build.
