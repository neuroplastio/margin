## What changed

The frontmatter feedback's two findings, both from the maintainer's own
diagnosis in the file: the frontmatter block was not reachable by keyboard, and
its too-long fields were truncated with an ellipsis. Both fixed:

1. **The block is a focus stop now.** `rebuild` no longer skips
   `blockFrontmatter`; it is entry 0, so `g` lands on it, `j`/`k` walk it, and
   focus-following scroll can bring it back into view once the reviewer has
   scrolled down (the feedback's exact complaint — `J`/`K` direct scrolling was
   the only way to see it before). `render` draws it through the shared block
   loop rather than ahead of it, so it gets the gutter focus bar, hover and
   hit-testing like everything else, and aligns with the prose below because the
   gutter column now provides the indent the old dedicated renderer hand-padded.
   What did *not* change is that it stays metadata: `commentable()` and
   `markable()` still exclude `blockFrontmatter`, so `c` says "nothing to
   comment on here", `space`/`r`/`f` say "nothing to mark here", and
   `reviewProgress` never counts it. The "no interaction" guarantee moved from
   the entry list (the old "not an entry at all" exclusion) to the two methods
   that already enforced it for comments and marks — the same guarantee, a
   defensible home for it once the block became reachable.

2. **Fields scroll horizontally instead of truncating.** The ellipsis is gone.
   `renderFrontmatterFields` renders every field at natural width and clips with
   `scrollCodeLine` — the exact code-block machinery — so a field wider than the
   measure scrolls with `l`/`h` (4 columns per press), clamped to field width
   minus measure, offset kept per-anchor in `m.codeScroll`. `scrollCode` was
   generalised to `scrollBlock`, covering `blockCode` and `blockFrontmatter` and
   drawing both through the same measure/offset logic; `move.dive`/`move.surface`
   treat the frontmatter like a code block (`l` scrolls right, `h` scrolls left).
   Rejected alternatives, briefly: wrapping (a continuation line would read as a
   second field) and keeping the ellipsis (it hides the value the field exists
   to show).

**Decided, not raised.** Search still excludes the frontmatter — `.32` shipped
that exclusion, and it stays, since `/` is for finding things in the document
and YAML fields are not it — but the exclusion is now an explicit guard in
`applySearch` rather than the side effect of the block having no span. One
consequence of the reachability change worth the maintainer's eye: a document
opens with focus on the frontmatter (it is entry 0), so the focus bar starts on
the top line of the block. If that reads wrong, the fix is a one-line
"start focus past the frontmatter" — cheap to unwind either way.

Answer:

- Focus starts on the frontmatter (the `▌` bar sits on its lines). Does
  opening on the metadata read as "the top of the document", or is it noise you
  will have to j-past every time — should the document open on the first real
  block instead, with `g`/`j` still able to reach the frontmatter?
- `l` on the focused frontmatter scrolls the `description:` field right, `h`
  back. Does that read clearly, or does a dim scrollable field with no hint
  that it scrolls feel more broken than the old ellipsis did? (The code block
  has the same property and was accepted — is frontmatter different?)
- `j` once from the top lands on the heading, `k` once returns to the
  frontmatter — does the block earning a focus stop make it feel like a real
  part of the document, or does a stop you can neither comment on nor mark
  still feel inert? (`c` and `space`/`r`/`f` on it say "nothing to comment /
  mark here" rather than doing nothing at all.)
- `/` then `title` — the frontmatter's `title:` does NOT match. Now that the
  block is reachable, should search cover it, or does excluding it still read
  as "metadata is not the document"?
- What I chose: a focus stop with the inert guarantee moved to
  commentable/markable, and the code-block horizontal scroll. What I rejected:
  wrapping long fields, keeping the ellipsis, and making the frontmatter
  searchable — all three felt like the wrong side of "metadata is not part of
  the document".
