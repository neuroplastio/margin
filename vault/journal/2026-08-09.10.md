## What changed

The maintainer reported that `ctrl+enter` does not submit a comment in the
composer. That report is the answer to the open question journal 2026-08-06.3
left behind: "does Ghostty actually report the modifier? If nothing happens, it
did not, and the intercept never fires. This is the one thing I could not
verify: the test proves our handling, not your terminal's reporting."

The handling was already right and remains untouched. `composer.sendKey`
(composer.go) checks `k.Code == uv.KeyEnter && k.Mod&uv.ModCtrl != 0` first and
resolves it to the same `:MarginSubmit` path as every other submit gesture. What
was missing was a test that pinned the **decode** half of that chain: the
existing `TestCtrlEnterSubmits` built the key by hand and fed it straight to the
composer, so if bubbletea ever stopped delivering the modifier — or if a terminal
sent a form margin could not decode — nothing in the suite would notice.

`TestCtrlEnterDecodesThroughRealReader` (marks_test.go) closes that gap. It feeds
the raw kitty keyboard-protocol sequence a modifier-reporting terminal sends for
ctrl+enter (`CSI 13;5u`) through the same `uv.TerminalReader` bubbletea v2 uses,
asserts the decode comes out as `{Code:13, Mod:ModCtrl}`, routes it through
`handleKey` into the live composer, and asserts the child submits with the typed
text saved. Verified the full path against the real binary in a pty: the thread
file lands on disk. The decode is now provable — what remains unprovable is
whether a given terminal actually reports the modifier, which is a property of
the terminal, not of margin.

Also recorded as F16 in `vault/knowledge/findings.md`: the ctrl+enter modifier
only exists if the terminal reports it, exactly the shape F1 already documented
for shifted keys. On a terminal that reports neither kitty nor modifyOtherKeys,
ctrl+enter is indistinguishable from enter and just inserts a newline — no margin
change can fix that, and the interaction contract already says so.

## Demo

```
make build && ./bin/margin README.md
```

1. `j`/`k` onto a paragraph, press `c`, type a few words, press `ctrl+enter`.
2. The composer should close and the comment should appear in the thread.
3. If nothing happens (or a newline is inserted), the terminal did not report
   the modifier — margin's intercept never fired, exactly as the 2026-08-06.3
   journal predicted. Confirm by pressing `ctrl+s` (nvim-side, works on any
   terminal): if that submits and `ctrl+enter` does not, the key itself never
   reached the host with the modifier attached.

Questions: which terminal is the maintainer running? If Ghostty, does its config
or version report Enter with the ctrl modifier (the kitty protocol)? The code
path and the decode are now both proven; the terminal is the only link left.
