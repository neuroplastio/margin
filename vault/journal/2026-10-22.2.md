# 2026-10-22.2 — A slow host is not a deaf one

Kind: mech (a host that answers every measure keeps its surfaces, however
long the wave takes in all).
Task: the maintainer's 2026-10-21 report, its second margin-side item: "Go
ahead on the issues you mentioned".
Commit: (this one)

## What changed

- A wave of measures gave up 3 s after it was sent, answered or not: any
  measure still out then made margin deaf, and everything went to cells for
  the rest of the run. A host that answers one measure at a time could trip
  it with a big wave (plx did, about 34 ms a measure, before 7ed3b836).
- Now the timeout gives up only when `hotMeasureWait` passes with no answer
  at all. `hotState.heard` counts the answers; the timeout carries the count
  from when it was set, and if answers came since, it waits again from
  there. So a wave goes deaf 3–6 s after its last answer, not 3 s after it
  was sent.

## Tests

`make check` and `make test-race`. `TestHotMeasureWaitsOnASlowHost`: a wave
answered once since its timeout was set waits again rather than going
deaf; a wave with no answer since does go deaf. It fails with the
`heard` check off.

## Notes

- Not felt: nothing changes on a host that answers within 3 s, and plx now
  answers a wave together (7ed3b836). The one difference is on a slow host:
  margin keeps the surfaces where it used to drop to cells.
