## What changed

The 2026-08-09 todo-review feedback deferred "dive into multi-line blocks"
until the L12-18 line-reference work (journal 2026-08-09.22) gave a line a
payload — a comment prefixed `L12-18: `, a yank of `file:L12-18`. That work
landed, so the dive now extends from threads to block lines:

1. **Line dive:** `l` on a block whose source lines each render as a row — a
   `blockTable` or a `blockRaw` — moves focus onto its first source line
   (`m.at.line`, a new field on `cursor`). `j`/`k` walk the block's source
   lines within `[b.line, b.endLine]`, and — mirroring the thread dive — `j`
   past the last line lands on the next entry, `k` past the first surfaces
   back onto the block. `h` surfaces. Implemented as new branches in `dive()`,
   `surface()` and `moveFocus()` plus a `lineDiveRange()` helper
   (`internal/review/review.go`), routed through the same `move.dive` /
   `move.surface` commands as the thread dive.

2. **The payload:** `c` while line-dived prepends `L<n>: ` to the comment
   draft (the single-line form of the L12-18 range), and `gy`/`yr` yanks
   `file:L<n>` — both now prefer the focused line over the whole block's range.

3. **Rendering:** at block level a focused block carries the focus bar on
   every rendered row; line-dived, the bar rides only the dived source line's
   rendered row, since for the diveable kinds rows and source lines coincide
   1:1.

**What was rejected:** line-diving paragraphs, quotes and list items — wrapped
prose re-wraps its source lines, so a "line" there has no row of its own to
stand on and the dive would be a stop with nothing to see (the same reasoning
that kept the original dive thread-only until a payload existed). Code blocks
too: `l`/`h` already scroll a focused code block horizontally (journal
2026-08-09.27), and one key doing two jobs is worse than this dive missing a
kind. Both are cheap to add later if the maintainer wants them.

## Demo

```bash
make build && ./bin/margin testdata/sample.md
```

1. Press `j` repeatedly until focus is on the table under "### What changes"
   (the | Component | Before | After | table, ~line 46). Press `l` — the focus
   bar should move onto the table's first row, and the block's other rows lose
   their bars.
2. Press `j` / `k` — the bar walks the table's rows, one source line per
   press, and pops out onto the next block at the bottom / back onto the table
   at the top.
3. Press `j` to a middle row, then `c` — the composer opens with the draft
   prefixed `L48: ` (or whatever source line) ready for the comment. Submit and
   the comment carries the line reference.
4. Stand on a row and press `gy` (or `yr`) — status reads
   `yanked reference sample.md:L48` and the reference is on the clipboard.
5. Press `h` at any point — the bar spreads back to the whole block.

Questions for maintainer: does diving a table by source line read clearly, with
the bar on the one row? Is `L48: ` the right prefix shape for a line-level
comment — or should it match the visual selection's `L48-51: ` range when the
dive covers more than one row? Does the exclusion of code blocks (they keep
`l`/`h` for horizontal scroll) feel right, or should the line dive take the key
and the scroll move elsewhere?
