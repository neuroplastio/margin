## What changed

`D` (`thread.delete`) was a comment/thread tombstone toggle: focus on a comment
tombstoned that comment, focus on a thread row tombstoned the whole thread. A
*draft* — unsubmitted text — was not part of that model, so pressing `D` on one
did the wrong thing or nothing: on a thread row holding only a draft it called
`toggleDeleteThread`, which with no active posted comments reported "thread
restored" and touched nothing; on a comment with an unsaved edit it tombstoned
the whole comment, throwing away committed text to discard an uncommitted edit.

`deleteFocused` now checks the focused thing's draft state first, mirroring the
precedence `editTarget` already used for `e`:

- **An unsaved edit of a posted comment** — focus on the comment, or on the
  thread row with no new-comment draft but a pending edit — `D` discards the
  draft, leaving the comment at its posted text (`edit discarded`).
- **A half-written new comment** — `D` discards it (`draft discarded`). A
  thread that held nothing but the draft is dropped and focus returns to the
  block, the same empty-thread rule `dismiss`'s cancel-early path applies.

Neither path writes the thread file or the event log: a draft is not committed
review state, so an agent tailing the log sees nothing, exactly as it sees
nothing when a draft is kept or discarded in the composer. The on-disk draft
(`clearDraft`) is removed so nothing resurrects on reopen.

The shared `draftAtFocus` helper names the target for both the delete and the
palette title, so `D` and `: thread.delete` never disagree about what a press
will discard.

**What I chose and rejected:** discard the draft *instead of* tombstoning the
comment/thread (the feedback's "delete it" reads as "the draft goes away", and
tombstoning a comment to discard an edit throws away what was already posted);
precedence matching `editTarget` (focused comment's edit first, then the
new-comment draft, then a pending edit on the row) so `e` and `D` always act on
the same thing; dropping a draft-only thread over leaving an empty "no comments
yet" row; no event-log line for a draft discard over emitting one.

## Verification

`make check` green (build, test, vet); `make test-race` green too — nothing
here touches the composer or the pty goroutine, but the leg drives draft
state that the render goroutine reads, so the race gate was run. New tests in
internal/review/draft_delete_test.go: discarding a new-comment draft on a
draft-only thread drops the thread and clears the on-disk draft; the same
discard on a thread with posted comments keeps the thread and its comments
untombstoned; discarding an edit draft keeps the comment at its posted text
(no tombstone, body unchanged, on-disk draft cleared); discarding a pending
edit from the thread row (editTarget's precedence); and `deleteTarget`
naming "draft", "unsaved edit to comment by toly", or "thread" by focus.

## For the maintainer to look at

Whether `D` on a draft should discard the draft as built — versus tombstoning
the comment or thread underneath, or prompting first — and whether dropping a
thread that held only the draft is the expected outcome for a new comment
discarded from the thread row.

## Demo

```bash
make build
printf '# Doc\n\nProse here.\n' > /tmp/draftdel.md
./bin/margin /tmp/draftdel.md
```

1. **A draft discarded.** Press `j` onto "Prose here.", then `c` to comment,
   type something, and `esc esc` to keep it as a draft — the thread row now
   reads `✎ draft · …`. Press `D`. I chose discarding the draft text over
   tombstoning: the draft should vanish and, since the thread held nothing
   else, the whole thread row disappears and focus returns to the block. Does
   that match what you expected `D` to do here?
2. **An edit discarded.** `c` again, type a real comment, submit
   (`ctrl+s`). Then `e` to edit it, change the text, `esc esc` to keep the
   edit as a draft — the comment shows `✎ edited, unsaved`. Press `D`. The
   comment should revert to its posted text with nothing deleted. Is reverting
   (not tombstoning) the right reading of "delete the draft"?
3. **Draft on a real thread.** Press `c` a third time, type a half reply,
   `esc esc`. The thread now has one posted comment plus a draft. Press `D` —
   only the draft goes, the posted comment stays. Press `D` again — the
   comment is tombstoned as before. Is a draft-discard then a separate
   thread/comment-delete the right progression?
