# 2026-10-02.4 — Web images on a host that allows them

Kind: felt (whether a web image loads, and how the page reads while it
does, needs a host with network images turned on and the maintainer's eyes;
which images stay images is mechanical and tested).
Task: maintainer direction — "I think margin should allow loading images
via https by default".
Commit: (this one)

## What changed

- **An https image the host allows stays an image.** HOTTY's network policy
  has two halves (SPEC §7.2): the host's, in its capabilities
  (`net["img-src"]`), and the document's, a `<meta name="hotty-network">`.
  A fetch happens only where both allow it. margin now writes the
  document's half, `img-src https:`, into every block that has an https
  image, and keeps the image as an image when the host's half lets its
  origin in (`https:`, the origin, or the origin with `:443`). Otherwise it
  becomes a link, as before.
- margin fetches nothing itself. The host does, under its user's policy.

## Notes

The first instinct was to fetch the images in margin and send them in-band
like local ones. The maintainer pointed out the host already fetches, by
design, under its own opt-in, and the document only has to ask. The
xterm.js addon fetches. hotty-blitz (hottyterm) fetched nothing yet, and
that is being added in its own repo.

A web image that loads after the block was measured makes the block taller
than its rows. That is the next leg: HOTTY's `fit` (SPEC §5.2), drafted for
it.

## Demo recipe

In hottyterm with https images allowed (or the xterm.js addon), open a
document with `![x](https://upload.wikimedia.org/wikipedia/commons/4/47/PNG_transparency_demonstration_1.png)`:

1. The image shows inline in its paragraph once it loads.
2. With the host's network policy off, it is a link to the URL instead.

Questions: is a link the right fallback, or should it be the alt text? Does
