## What changed

The gutter's mark column no longer repeats an icon on every line of a marked
block — a six-line reviewed paragraph used to show six `✓`s, which the
maintainer judged "weird". It now draws a **vertical rule** (`│`) in the
mark's colour on each of the block's lines (`gutter`, `internal/review/
review.go`), so the repetition reads as one continuous line down the block's
extent: green (`114`, the old `✓` colour) for reviewed, orange (`209`, the
old `!` colour) for flagged. Blank separator lines between blocks carry no
gutter, so the rule spans exactly the marked block and stops.

Decisions made, and what they replaced:

- **Headings take the rule too.** A section roll-up used to show a single
  `✓`/`!` on the heading line; it now shows the same coloured `│` there.
  Rejected: keeping the icons on headings as a "summary" marker — that
  splits the column into two visual languages, and the feedback's "replace
  with sleek vertical lines" does not carve headings out. Colour, not shape,
  carries the state everywhere in that column now.
- **The partial roll-up keeps its dimmed `·`.** interaction.md settles
  "partial coverage renders as a dimmed ·", and this feedback is about mark
  icons, not the partial treatment — the one cell in the column that is not
  a rule.
- **`reviewMark.glyph()` survives**, now used only by the plain-text
  quit-time summary (`^a1 [✓]` after exit, review.go's `Run` tail) — a text
  report, not the gutter, where `✓`/`!` is the more legible encoding.
- Widths are untouched: `│` replaces the icon in the same single column, so
  `gutterW` stays 3 and no hit-test, wrap or pane math moves.

## Verification

`make check` green (build, test, vet). Render-only change in the host's
render path — no composer or emulator touch — so `make test-race` is not
required by the gate.

New tests (`marks_test.go`): `TestMarkRendersAsGutterRule` pins that every
text line of a reviewed block carries the green rule (on a paragraph seeded
long enough to wrap, so continuity is actually pinned), a flagged block
carries the orange one, the retired icons are gone from both, and an
unmarked block's gutter stays blank. `TestPartialSectionKeepsDimmedDot` pins
the settled partial treatment against the rule swap — mixed section → dimmed
`·` on the heading; fully reviewed → the heading trades the dot for the
green rule.

What I cannot verify: whether a one-cell-wide coloured rule reads as
"reviewed"/"flagged" at a glance, whether the colours still scan down a long
page the way the icons did, and whether a single-line block (a heading, a
short item) carries enough rule to notice — that is the demo below.

## Demo

```
make build && ./bin/margin testdata/sample.md
```

1. `j` onto a multi-line paragraph, `r` — a green vertical rule should run
   down every line of the block, no `✓` anywhere. `f` — it turns orange.
   Does the rule read as a mark at a glance, or is it too quiet next to the
   prose?
2. Mark one paragraph in a section `r` and another `f`, then look at the
   section's heading — the heading shows the dimmed `·` (partial), not a
   rule. Mark the rest reviewed — the heading picks up the green rule.
3. Mark a single-line block (a short list item or a heading-sized paragraph)
   — is a one-cell rule enough signal, or does it vanish?
4. Scan a page with several marked blocks — do the rules line up and read as
   a column, or do you miss the icons?

Questions: is `│` the right weight (over a heavier `┃` or the focus bar's
`▌`), and are green/orange still the right colours now that the area is one
cell per line instead of a glyph? Chose a continuous `│` rule in the
existing mark colours, over keeping icons on headings (two visual languages)
and over a heavier bar (the focus/selection/hover bars already own `▌` in
the adjacent column — a heavier mark bar would fight them).
