## What changed

The feedback: "Editing a comment and exiting without changing anything and
without saving marks it 'unsaved draft' — but nothing changed. If there is no
diff, do not mark it as a draft."

It did: `e` on a posted comment opens the composer with the comment's text, and
any exit on the draft path — a single `<Esc>` in normal mode, `:q`, `SPC c d`,
or blur — called `t.setDraft(target, body)` unconditionally, so closing a
comment you never touched left a draft whose text was byte-identical to the
posted comment and a "edit kept unsaved" status line. A thread with a pending
edit then read as having one (`✎ draft` on its collapsed line) even though
nothing was ever changed.

The fix is in `dismiss`'s `outcomeDraft` branch (`internal/review/review.go`):
an edit of a posted comment (`target` names a real comment) whose body equals
that comment's body is **unchanged** — clear any draft the target held (thread
and draft cache), and say so (`no changes`). Anything else keeps the existing
behaviour: a genuinely edited comment keeps its draft, a blank buffer closes
with no draft, a new comment's text always keeps one.

**What I chose and rejected:** the baseline is the posted comment itself, not
the seed the composer opened with — a resumed edit that *reverts* to the posted
text also clears its stale draft, which is the same statement ("no diff") from
the other direction, and it quietly cleans up drafts the old behaviour left
behind that were equal to the comment they shadowed. A new comment has no
baseline, so it keeps a draft whenever it has text; the line-reference prefix
edge (journal 2026-08-09.38's open question) is deliberately untouched by this
leg. Chose the targeted `if` over a general "same as the seed, no draft" rule,
since that rule would also fire on a fresh empty buffer and change behaviour the
feedback never asked about.

## Demo

```bash
make build && ./bin/margin testdata/sample.md
```

1. `l` into a thread, `j` to a posted comment, `e` — the composer opens with the
   comment's text in normal mode. Press `esc` once without touching a key. The
   composer closes; the status line reads `no changes` and the thread's
   collapsed row shows **no** `✎ draft` marker. (Before this leg it said
   `edit kept unsaved` and the comment carried a draft identical to itself.)
2. Same `e`, but now type an edit (`a`, some words) and `esc` — the draft
   marker does appear, with your edit kept; the posted comment is still
   untouched. Resume it with `e` and it opens with your edit.
3. The new-comment path is unchanged: `c` on an uncommented block, type half a
   comment, `esc esc` — draft kept as before.

Questions for the maintainer: is `no changes` the right status wording for a
closed-but-unchanged edit, and is clearing a reverted stale draft (rather than
keeping it) the behaviour you want? And does the `esc keep` footer hint (escHint,
unchanged) still read correctly now that a bare `esc` on an unchanged edit
leaves nothing behind?
