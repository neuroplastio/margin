## What changed

The feedback, verbatim: "Raw mode currently loses color (syntax highlighting);
it should keep colors."

`renderRaw` drew every source line as plain text, so flipping `\` to check the
source of truth dumped chroma's whole palette — the one colour the rendered view
had added was gone. `renderRaw` now pre-computes `highlightCode(e.b.lines,
e.b.lang)` for every code block entry and, when a source line sits *inside* a
fence (`li - b.line` in `[0, len(hl))` — `b.line` is the 1-based fence-open
line, so the first content line is `b.line+1` → 0-based `b.line`), renders the
chroma-styled content line instead of the raw byte. Fence lines themselves
(` ``` `) stay plain source, and the map is skipped for an empty fence
(`len(e.b.lines) == 0`), so the closing fence of an empty block cannot map into
a bogus highlight.

**What I chose and rejected:** only the code content borrows colour — the
paragraph, heading and list source lines stay verbatim, because raw mode's whole
reason to exist is "the exact bytes as written" and chroma is the only part of
the rendered view whose colour *is* the content rather than a decoration on it.
I rejected styling the fences (they are syntax, not code — the same line
RENDER-02 already drew) and rejected a full inline-markup pass over the raw
source (RENDER-06's `**bold**` styling would re-interpret bytes raw mode exists
to show uninterpreted).

`selLine` and `applySearch` already handle ANSI-bearing lines (that is what
`selLine` was built for), so selection and search behave on the highlighted
lines without change.

## Demo

```bash
make build && ./bin/margin testdata/sample.md
```

1. Press `\` to switch to raw mode. `j` down to the go code block (fence at
   line 62). Its body — `func retry`, `return nil`, the closing `}` — should
   carry the same chroma/monokai colours the rendered view showed, while the
   ```go and ``` fence lines read as plain source. Judge: is highlighting the
   code content (not the fences) the right amount — does raw mode still read as
   "the source, verbatim", or should the fences be dimmed/styled too?
2. Scroll to a paragraph in raw mode — plain, as before. Judge: should *any*
   other markup (`#` headings, `**bold**`) get colour in raw mode, or does that
   defeat the point of a verbatim view?
3. Press `\` back to rendered, then `\` again — the toggle both ways keeps the
   viewport anchored on the same block, and the highlighted lines do not shift
   or wrap anything.

Questions for the maintainer: is chroma-on-code-only the right scope for raw
mode colours, and does the highlighting survive the `\` round-trip without
visually distracting from the verbatim source?
