## What changed

- **`--version`** ends with the hotty version margin speaks, hotty-go's
  `hotty.Version`: `margin 26.11.02 (<commit>) · hotty 0.5`. The release
  workflow's `cut -d' ' -f2` still reads the name alone. margin has no About
  window.
- **The GitHub release** is titled `margin <tag> — hotty <X.Y>`, and its
  notes start with `<tag> — hotty <X.Y>`. The release job reads the version
  from the build's own `--version`, and fails if it names none.
- **The packages.** The Homebrew desc ends with ` (hotty 0.5)`, and the
  AUR pkgdesc with `, speaking hotty 0.5`. Each publish script reads the
  version from the release's margin for the machine it runs on. A release
  from before margin said one renders no hotty part.
- The Homebrew desc is shorter ("Terminal tool to review markdown and hand
  comments back to an agent"). With the hotty version it is 79 characters,
  under `brew audit --strict`'s 80.

## Tests

`make check` and `make test-race`. `TestVersionFlag` wants the hotty
suffix. The update tests compare whole `--version` lines with it.

`packaging/homebrew/publish.sh 26.10.21 --render` renders a desc without the
hotty part (26.10.21 doesn't say one). `packaging/aur/publish.sh 26.10.21`,
not pushed, finds the same PKGBUILD as the AUR's, so it doesn't republish
the package. I checked the labeled path with a local build's label
(`… · hotty 0.4`): ` (hotty 0.4)` and `, speaking hotty 0.5`.
