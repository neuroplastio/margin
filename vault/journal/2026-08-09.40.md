## What changed

The feedback: "Starting a new comment and immediately cancelling currently
creates an empty thread showing 'no comments yet'. It should not. Cancelling
before anything is committed must not create a thread at all."

It did, because `c` opens the composer through `ensureThread`, which creates an
empty thread in `m.threads` up front (the thread row has to render under the
editor while the reviewer writes, and the draft has to live somewhere). Nothing
ever removed that thread when the composer closed having received nothing, so a
cancel left a "no comments yet" row behind on every thread-less block the
reviewer touched.

The fix is in `dismiss` (`internal/review/review.go`), which already applies
every composer outcome: a thread that `ensureThread` **created for this open**
(`m.freshAnchor`, set on creation) and that now holds no posted comment, no
draft and no resolved flag is dropped, with focus put back on the block the
aborted comment was about — the thread-row entry, if focus sat on it, vanishes
with the row. Every cancel path converges here: double-`esc` on an empty new
comment, an empty `ctrl+enter` submit ("nothing to submit"), `:q!` discard, and
blur. The `newComposer`-fails edge gets the same drop (no composer ever opens,
so dismiss never runs).

**What I chose and rejected:** the first cut dropped *any* thread left empty by
a dismissal — simpler, no new state. It broke `TestSpacemacsDiscard`: a `:q!`
on the seeded draft-only thread `^e5` empties it, and the unconditional check
would have deleted a thread that existed before the open. The feedback asks only
that cancelling not *create* a thread, so I scoped the drop to threads the open
itself created (`m.freshAnchor`), which can never delete a thread that pre-dates
the composer and so can never lose a thread file. Chose that over also dropping
emptied pre-existing threads; if the maintainer wants the stricter rule it is
one `&&` removed. A kept draft still keeps its fresh thread (the draft is
content, and `:q!` on a resumed draft still discards only the draft, not the
thread); a cancelled edit keeps the thread it belongs to.

## Demo

```bash
make build && ./bin/margin testdata/sample.md
```

1. `g`, `j` to a paragraph with no thread (any uncommented block), `c` — the
   composer opens. Press `esc esc` with nothing typed. The composer closes, and
   **no** "no comments yet" thread row appears; the block below the one you
   tried to comment on is not skipped either — focus is back on the block.
2. Same `c`, then `ctrl+enter` on the empty buffer — "nothing to submit", and
   still no empty thread row.
3. `c`, type half a comment, `esc esc` — the thread *does* appear with the
   draft (`✎ draft · half a comment`), and `c` again resumes it. A cancel with
   nothing kept is the only thing that leaves nothing.
4. `e` on any existing comment, `esc` — the thread stays, exactly as before;
   only freshly-created, never-committed threads can disappear.

Questions for the maintainer: is focus landing back on the block the right
resting place after an aborted comment, and does the draft-keeps-thread edge
read as consistent — the empty cancel leaves nothing, but a half-typed one is
still preserved? And is dropping only freshly-created threads the right scope,
or should a `:q!` that empties a pre-existing thread leave it behind as a
permanent row?
