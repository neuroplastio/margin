## What changed

The navigation-feature feedback's third request: a toggle that switches
between the rendered document view and the raw markdown source of the same
document. The three open questions the feedback named are settled by this leg,
as it said they should be, not raised:

1. **Which key toggles it — `\`.** Unbound before this, on the home row, and
   reading as "show me the raw". Rejected: `x` (vim's delete-char muscle
   memory) and `z` (vim's fold family). Reachable from the palette too, as
   `view.raw`, like every other command.

2. **Raw mode renders `m.src`, the exact bytes loadDoc/loadDocFrom read — not
   the reconstructed blocks.** The feedback asked whether it reuses the
   blockRaw/verbatim path; it goes one further and skips reconstruction
   entirely. `renderRaw` splits the source on newlines and draws one rendered
   line per source line, verbatim, no re-wrapping, no inline styling — what you
   asked to see is literally the file. Each block's span is its source-line
   range (`[b.line-1, b.endLine-1]`), so hit-testing, clicks, page keys and
   focus-following scroll work in raw mode exactly as in rendered mode. The
   gutter stays: the focus bar rides the focused block's source lines and the
   mark rule rides a marked block's, so focus and marks keep their meaning. The
   source is kept because the model needs it for the toggle — `m.src` is set in
   `Run` (both file and stdin paths), and `loadDoc`/`loadDocFrom` now return it
   alongside the blocks.

3. **Focus and scroll survive the switch.** `toggleRaw` re-finds the focused
   block by *anchor*, not index — rebuild drops thread rows while raw is on
   (threads are conversation in `.margin/`, not part of the document), which
   shifts entry indices — and resets `scrollAnchor` to the sentinel so
   `clampScroll` re-anchors the viewport to it on the next render. The reader
   stays where they were. Visual selection and comment/line dives are
   cancelled: a selection measured in rendered entries would shift under the
   rebuild, and raw mode has no line dive — every line is already visible. `l`
   / `h` (dive and code-horizontal-scroll) are inert in raw mode for the same
   reason.

**Decided, not raised:** threads are excluded from raw mode (they are not
source; rebuild leaves them out of entries); search runs over raw lines like
any others, so `/` finds a string in the source too (frontmatter stays
excluded, unchanged); a seed model has no source, so the toggle refuses with a
status line rather than rendering nothing. All three are the least-surprising
read of "the raw source of the same document" — threads and marks are review
layers, the raw view is the file.

## Demo

```bash
make build && ./bin/margin testdata/sample.md
```

1. Press `\` — the document switches to its raw markdown source: the `---`
   frontmatter, the `# Session storage migration` heading, every `|` of the
   table, the ``` ```go ``` fences — all verbatim, one source line per row,
   no wrapping. The focus bar sits on the block that was focused (the
   frontmatter if you opened and toggled immediately).
2. Press `j` / `k` — focus walks blocks; the bar rides each block's source
   lines. Press `space` on one — the mark rule appears down its source lines.
3. Press `\` again — back to the rendered view, focused on the same block.
4. Toggle to raw, press `/`, type a source-only string (e.g. `SESSION_REDIS`)
   — it highlights in the raw view too.

Questions for maintainer: is `\` the right key, or does it fight muscle
memory? In raw mode, does the gutter — focus bar and mark rule riding source
lines — help you keep your place, or should raw mode be a pure "the file,
nothing else" view? Is one-line-per-source-line the right fidelity, or should
long lines wrap/clip differently? And does keeping focus on the same block
across the switch read as "nothing moved", or should the viewport stay pinned
pixel-for-pixel when the line counts differ? (What I chose: `\`, gutter kept,
verbatim no-wrap, focus preserved by anchor. What I rejected: `x`/`z` as the
key, reconstructing source from blocks instead of keeping the bytes, wrapping
raw lines, and keeping thread rows in raw mode.)
